# Agent 适配器与禁止直接篡改

状态：已接受

Agent 集成通过内置适配器和声明式适配器清单完成，适配器按需实现发现、生成计划、激活、启动、健康检查和回滚能力。第一版不加载任意第三方 DLL 或脚本，也不直接修改未知 Agent 二进制和内部状态文件。选择该策略是为了把兼容性差异限制在明确契约内，避免一次配置修复破坏整个 Agent；代价是新增 Agent 支持需要单独开发和验证。

## 后果

- 无法完整支持某个 Agent 时，必须明确显示不支持的阶段和能力。
- 配置修改只通过已声明的路径、变量和启动参数进行。
- 健康检查必须实际验证工具调用能力，而不是只检查文件是否存在。
