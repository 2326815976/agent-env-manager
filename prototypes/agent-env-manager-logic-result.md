# 逻辑原型验证结果

## 验证问题

同一套计划式状态模型，是否能够安全表达环境扫描、纳管、版本切换、跨盘迁移、隔离删除、健康失败和回滚，并能在真实 Windows 路径与 `PATH` 解析中成立？

## 结论

核心方案可行。状态模型已经覆盖主要生命周期，真实 Windows 探针也验证了稳定入口、版本切换、失败检测和回滚所需的底层机制。

## 已验证

- 纯状态机六个关键断言全部通过：正常切换、迁移路径更新、健康失败回滚、系统 Shell 拒绝、跳过恢复点执行拒绝、拒绝后继续校验。
- 在临时目录中成功创建 Junction，无需管理员权限。
- 通过切换 Junction 改变同一个命令入口解析到的版本；子进程 `PATH` 能正确执行切换后的命令。
- 模拟损坏版本时健康检查能够识别失败，切回稳定版本后恢复成功。
- HTML 原型可由 Microsoft Edge 真实渲染，初始状态、四个引导场景和自由操作区域均正常显示。
- 当前 Codex CLI 为 `0.159.2`，`CODEX_HOME` 指向 `E:\Codex\.codex`，用户目录 `.codex` 是指向该位置的 Junction。

## 尚未验证

- ChatGPT 桌面端是否能通过启动环境或适配器稳定接收受管工具运行时。
- 大体积运行时的真实跨卷迁移性能、磁盘中断、文件锁和断电恢复。
- 持久写入用户或机器环境变量后的广播行为。
- Python、Node、Git、PowerShell 7 的官方制品下载、哈希校验和安装规则。

## 决策

可以继续设计并实现共享核心、CLI 和 WPF 界面。下一步应优先制作 ChatGPT 与 Codex 的最小真实适配器，在临时配置环境中完成“绑定、启动、健康检查、切换、回滚”的端到端验证，再扩大到其他 Agent。
